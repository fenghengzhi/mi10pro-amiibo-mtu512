# 原厂蓝牙库版本快照

每个快照目录按 `设备代号/系统版本/` 组织，内部保留原始设备路径。清单中的 SHA-256 应与二进制实际内容一致。

当前版本：[`cmi/V816.0.9.0.TJACNXM/manifest.json`](cmi/V816.0.9.0.TJACNXM/manifest.json)。它包含：

- `system_ext/lib64/libbluetooth_qti.so`：本模块的补丁输入，活动高通蓝牙栈。
- `system/lib64/libbluetooth_qti_jni.so`：配套 JNI 库，仅作升级比较基线，未打补丁。

两份文件均于 2026-09-28 从当前手机通过 ADB 提取；路径已与蓝牙进程映射核对。仓库不包含蓝牙配对数据库、设备序列号或用户通信数据。

## 检查当前快照

```sh
cd firmware/cmi/V816.0.9.0.TJACNXM
shasum -a 256 -c SHA256SUMS
```

Linux 也可以使用 `sha256sum -c SHA256SUMS`。

## 系统升级后追加

1. 在手机上停用相关蓝牙库替换模块并重启，确保读取的是升级后的原库。
2. 记录完整系统版本、Android 版本、安全补丁日期和系统指纹。
3. 按新版本创建目录；从设备重新确认实际加载的库路径，不能假定升级后仍沿用旧路径。
4. 提取相应原库，生成新目录的 `manifest.json` 和 `SHA256SUMS`，保留本次采集来源和日期。
5. 更新 `index.json` 并提交，保留旧目录。哈希相同表示对应文件内容相同；哈希不同需要重新分析其函数与补丁位置。

同一个版本号下如果库文件实际内容不同，为新采集另建带日期或哈希后缀的目录，并在清单中保留真实版本号，避免覆盖已有基线。

二进制按普通 Git 文件存储，可通过路径历史取回旧版本。清单是可读的变更记录，不应手动填写与文件不一致的哈希。
